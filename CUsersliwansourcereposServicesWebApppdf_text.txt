Security Findings
1. Provider API has zero authentication — exploit confirmed live
[CRITICAL]
Tested with
curl — no JWT token, only a spoofed x-user-id header
Routes affected
ALL 7 routes in /api/provider/* — no requireAuth middleware on any
Root cause
getUserId() in providerController.js reads req.userId (never set) then falls back to req.headers['x-user-id'] — a header any attacker controls
All four attacks executed successfully against the live server:
Read Carol's services — 200 OK with no token
 
Create service on Carol's account — 201 Created with no token
 
Delete Carol's service — 200 OK with no token
 
Overwrite Carol's display name, bio, availability — 200 OK with no token
 
---PAGE---
Fix: Add router.use(requireAuth) at the top of providerRoutes.js — one line.
Launch blocker: YES
2. JWT secret has a publicly known hardcoded fallback
[CRITICAL]
Location
middleware/auth.js and authController.js
Fallback value
"your-secret-key-change-in-production"
Impact
Any attacker can forge admin-role JWTs and impersonate any user if JWT_SECRET env var is not set in production
Fix: Remove the fallback. Throw a startup error if JWT_SECRET is missing.
Launch blocker: YES
3. No rate limiting on any endpoint
[HIGH]
Affected routes
POST /api/auth/login, POST /api/auth/register, POST /api/bookings, POST /contact
Risk
Login brute force, registration spam, booking spam, contact form abuse
Fix
Add express-rate-limit middleware to all public-facing and auth endpoints
Launch blocker: YES
4. /forgot-password renders a completely blank white page
[HIGH]
Tested
Navigated to http://localhost:3001/forgot-password
Result
document.body.innerText === "" — completely blank, no route exists in App.js
The link
Prominently shown on the login page as a clickable link
Fix
Remove the link or implement the route; either way do not ship a dead link
Launch blocker: YES

Bug Report
Bug 1 — CA$ currency symbol in provider services widget
Severity: High
Steps to reproduce
Log in as Carol → Switch to Provider Mode → My Services table shows CA$90, CA$38/hr instead of the correct PHP peso symbol.
Actual result
CONFIRMED LIVE — all 3 checked rows showed wrong symbol.
Suggested fix
Change const sym = "CA$" to const sym = "\u20b1" in ProviderServicesWidget.jsx line 297.
Priority
Must fix before launch
Bug 2 — Availability toggle makes zero API calls — doesn't persist
Severity: High
Steps to reproduce
Switch to Provider Mode → click the 'Available to clients' toggle → refresh.
Actual result
CONFIRMED LIVE — network log shows zero calls to PUT /api/provider/profile on toggle click. UI text changes but state is lost on reload.
Suggested fix
Wire the toggle click to PUT /api/provider/profile with the updated isProviderActive value.
Priority
Must fix before launch
Bug 3 — Provider dashboard bio is hardcoded
Severity: High
Steps to reproduce
Switch to Provider Mode as any user.
Actual result
CONFIRMED LIVE — all providers see 'Manage your services and bookings'. ProviderDashboard.jsx constructs the profile object from localStorage and hardcodes the bio string. No call to GET /api/provider/profile is made.
Suggested fix
Add a useEffect that calls GET /api/provider/profile on mount and uses the real data.
Priority
Must fix before launch
Bug 4 — No Reject button for pending users or services in admin panel
Severity: High
Steps to reproduce
Log in as admin → view Pending User Registrations.
Actual result
Only an 'Approve' button exists. No way to formally reject a bad actor's registration or an inappropriate service.
Suggested fix
Add PATCH /api/admin/users/:id/reject and /services/:id/reject endpoints and corresponding UI buttons.
Priority
Must fix before launch
